# 写注释说明

## 目标

让初学者读完注释就知道：模块做什么、接哪里、框架已做好什么、在哪调用、得到什么数据、哪些情况不能用。
以“短说明 + 实际调用 + 行尾解释”为主，不把头文件写成教程。

## 先核实，再写

1. 阅读目标头文件、对应实现；必要时检查初始化、调用位置、时钟和硬件资料。
2. 以当前代码为依据，不凭函数名猜范围、单位、失败返回值或接线。
3. 区分类型能表示的范围、驱动接受/返回的范围、硬件可测范围和实测精度。未验证的不要写成保证。
4. 用户只要求注释时，只改注释；不改接口、驱动、配置或应用逻辑，不顺便添加功能。

## 固定写法

按以下顺序组织模块顶部说明；不适用的部分省略：

1. **用途**：一句话说明输入是什么、输出是什么。
2. **硬件对应**：通道、器件编号、引脚、必要跳帽；只列已核实的内容。
3. **框架已完成**：初始化、周期更新、缓存等，避免用户重复操作。
4. **常用调用**：一行一个实际调用，行尾写类型含义、范围和单位。
5. **小案例**：一个最小场景，说明放在哪个函数、何时执行。
6. **注意事项**：非法参数、无效/过期数据、失败行为、硬件安全和调用限制。

默认模块总说明约20~40行；复杂模块按需增加，不为凑齐格式重复解释。
函数声明旁通常补1~3行说明即可；不要把顶部内容在每个函数前重新写一遍。

## 接口必须说清的内容

- 参数可填哪些值，编号对应哪个实物；特别区分软件通道和硬件外设编号。
- 返回数据的类型、实际范围、单位。例如float频率是Hz，占空比是0~100%，不是0~1。
- 返回值表示数据还是状态。分别解释HAL_OK、1/0，不混用成功条件。
- 无效时返回0、保留旧值还是不修改输出变量；是否需要检查有效标志。
- 读取是否仅取缓存、会不会清事件、是否等待新数据；初始化是否已调用。
- 写入类接口说明允许范围、是否限幅、何时写一次，不让示例每轮反复写存储器。
- 有限制时说明刷新周期、分辨率、超时；不能把float小数位数当作测量精度。

## 示例规则

- 使用项目中真实存在的接口，不虚构函数。
- 优先采用“类型 变量 = 函数(参数); // 含义、范围、单位”的写法。
- 输出参数使用匹配类型的变量和正确的&；数组传数组名，必要时一句话解释。
- 示例短且能嵌入当前框架；指定插入位置，不自动放入业务代码。
- 需要时检查返回值，只有成功后才使用结果。每个例子专注一个目的。
- 默认只给一个小案例；用户要求多种类型时，追加各类型的短调用，不重复整套流程。
- 只对容易误解的内容补一句原理，如&变量、sizeof、字节和显示字符的区别。

## 存储模块的额外要求

用简表列“类型 / 字节数 / 对应读写函数”，并举不重叠的起始地址。
字节数基于当前目标和工具链核实；不宣称C语言在所有平台都固定如此。
例如本工程float为32位，即4字节，与1.65有几位数字无关。
字符串要计入结尾的'\0'；不要按中文字符数量推断字节数。
说明读写保持相同类型、地址和长度；不要反复写入；通信成功不等于内容有效。

## 风格范例

以下是写法示范，具体数值、接线和初始化必须以目标工程核实结果为准：

~~~c
/*
电位器 / ADC：把输入电压读成数字。框架已校准并初始化。
通道1：R37，J11跳帽接好，PB15 / ADC2_IN15。
ADC_Proc()已每20ms更新缓存，应用只读数，不需要重复启动ADC：
  uint16_t raw = Analog_GetRaw(1);        // 原始值0~4095
  uint16_t mv  = Analog_GetMillivolts(1); // 默认参考下0~3300，单位mV
  float v     = Analog_GetVoltage(1);    // 默认参考下0.000~3.300，单位V
  uint8_t p   = Analog_GetPercent(1);    // 0~100，单位%
  if (Analog_IsValid()) { ... }         // 最近一次三路采集均成功才使用
小案例：在UART_Task()每500ms输出一次电压：
  UART_SendFloat(Analog_GetVoltage(1));
  UART_SendString(" V\r\n");
通道只填1/2/3，非法通道返回0；未成功采样时缓存为0，请结合IsValid。
参考电压默认3300mV，可根据实测VDDA调整换算参数。
只允许0~VDDA输入，不能接5V；更新在主循环执行，不在中断采样。
*/
~~~

## 完成前检查

- 是否不看实现也能知道怎么调用、读到什么范围和单位？
- 返回0时究竟是正常数据还是无效结果，是否写清？
- 是否核实通道、引脚、时序，没有夸大硬件精度或验证程度？
- 是否只有必要示例，没有长篇重复、无关理论和无授权代码改动？
- 回读修改，确认注释闭合、原声明和代码不变。仅改注释时不声称已做实物验证。
- 最后简短告知修改路径和主要补充内容，不把整篇注释再复制到回复。
